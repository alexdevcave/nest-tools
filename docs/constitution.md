# Constitución — Nest Tools Workspace

Principios innegociables para la app y para la librería publicada en npm. Si un cambio choca con uno, se cambia el cambio o primero se enmienda esta constitución.

1. **Stack mínimo.** Solo lo ya instalado (NestJS, Nx, pnpm, TypeScript, Jest, webpack). Una dependencia nueva exige una spec que la justifique y aprobación explícita. _Se comprueba:_ `package.json` solo cambia junto a una spec aprobada.
2. **La spec manda.** No hay código sin `specs/NNN-nombre/spec.md` aprobada. Cada FR de comportamiento tiene al menos un test cuyo nombre lo cita, y cada FR de configuración o de proceso (empaquetado, release) tiene un comando de comprobación documentado en el plan. _Se comprueba:_ cada FR aparece en algún `it('FR-n …')` o en la verificación del plan.
3. **Lógica separada de Nest.** Las reglas, cálculos y formateos viven en funciones o servicios sin decoradores; controladores, filtros, interceptores, pipes y decoradores solo conectan esa lógica con Nest. _Se comprueba:_ la lógica tiene tests unitarios que no levantan un módulo de Nest.
4. **Tests con lo que ya hay.** Jest + `@nestjs/testing` para unidades y Jest + axios para e2e; no se instalan librerías de test. Cada export público de la librería tiene al menos un test. _Se comprueba:_ `pnpm nx run-many -t lint test build` en verde antes de cerrar una tarea.
5. **Datos del usuario protegidos.** Toda entrada se valida antes de llegar a la lógica. Las respuestas nunca exponen datos personales, secretos, cabeceras de autenticación ni trazas internas. Los logs pueden llevar la traza de los errores del servidor, pero la app y la librería no registran por su cuenta bodies, cabeceras, query strings ni secretos; el contenido de los mensajes de error es responsabilidad de quien los escribe, y la librería documenta qué registra. _Se comprueba:_ tests de entrada inválida que esperan `400`, tests de que un `500` no incluye el `stack` y tests de que los logs de la librería no incluyen body, cabeceras ni query string.
6. **Idioma.** Código, nombres, comentarios, JSDoc, mensajes de la API y el README publicado en npm, en inglés; specs, docs internos y textos para el equipo, en español. _Se comprueba:_ revisión del diff.
7. **Librería pública estable.** La API pública es solo lo que exporta `libs/nest-tools/src/index.ts`, sigue semver y su propio código no hace nada solo por importarse (lo que hagan NestJS u otras dependencias de pares al cargarse no cuenta). Desde la 1.0.0, un cambio incompatible es versión mayor; mientras sea 0.x, sube el minor, y `feat` y `fix` suben el patch. NestJS y `rxjs`, si se importan (aunque sea solo para tipos), van en `peerDependencies`, en `dependencies` solo `tslib`, y nunca se importan `express` ni `fastify` directamente. _Se comprueba:_ `libs/nest-tools/package.json` y un grep de imports en `libs/nest-tools/src`.

Enmiendas: 2026-11-14 — librería pública en npm (principio 7; ajustes en 1, 3, 4, 5 y 6). 2026-11-14 — verificación de FR de proceso (2) y semver en 0.x (7). 2026-11-14 — peers solo si se importan (7). 2026-11-14 — respuestas frente a logs (5). 2026-11-15 — efectos propios al importar y peers aunque sean solo tipos (7).
